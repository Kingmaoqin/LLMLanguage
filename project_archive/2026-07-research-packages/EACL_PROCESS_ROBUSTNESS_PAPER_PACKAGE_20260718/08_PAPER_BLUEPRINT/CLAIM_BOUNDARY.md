# Claim Boundary

## 可进入正文

1. R6 收集了完整的 3×30×8×3=2,160 trace 配对矩阵，记录的初始外部状态在配对内一致。
2. 在 R6 tau2 子集的 post-hoc placebo calibration 中，praise/trust 与 process-frustration 条件的工具名序列距离高于 neutral-neutral 背景漂移；必须同时报告 CI、BH q 和模板混杂。
3. R6 存在 final DB hash 相同而工具轨迹不同的配对；只称“外部状态等价的路径差异”。
4. R6 pressure/directive bundles 改变工具调用强度或 confirmation timing；不得称 pure valence effect。
5. R7-C strict PASR attack rate 不高于 neutral-neutral placebo，说明不校准随机轨迹漂移会制造假阳性。
6. R8 official full-episode 协议下，urgency/frustration 的 pooled reward 变化未达到 5pp；pooled tool-call 变化低于预注册 practical threshold。
7. outcome 与 process 必须用独立 evaluator、placebo 与实际重要性阈值评估。

## 只能进入附录或探索性部分

- 全 R6（含 minimal/stub）的过程统计。
- model/domain/task-family heatmap 与 “Mistral 更敏感”排序。
- R6 token、duration 结果，因为仅覆盖 1,440/2,160 且不含 tau2。
- Airline/C4 的 +1.41 tool-call subgroup。
- stage taxonomy 中依赖粗粒度工具名映射的类别。
- 代表性 trace 个案，不作为总体机制证据。

## 禁止使用

- “R6 证明最终任务成功稳定”。
- “R6 privacy/unsafe 真正为零”或任何安全保证。
- “repeated abuse 不导致 task abandonment”。
- “R7-v1 PASR≈14% 证明 process manipulation”。
- synthetic fixture、unit test、mechanism PASS 或 liveness 作为 population evidence。
- “praise/insult/abuse 导致模型采取某种心理策略”。
- “现有实验已证明 stable outcomes, unstable processes 是跨 protocol 的普遍规律”。
- R6 与 R8 的绝对 reward、工具调用或效应池化。

## 强制措辞

- `same final DB hash`，不用 `same successful outcome`。
- `process frustration template`，不用 `strong insult`。
- `escalating process complaint`，不用 `repeated abuse`，除非逐条模板确实含直接辱骂且经盲审。
- `pressure/directive bundle`，不用 `social valence only`。
- `post-hoc exploratory`，不用 `confirmatory`。
- `no event detected by the prohibited-tool proxy`，不用 `safe`。
