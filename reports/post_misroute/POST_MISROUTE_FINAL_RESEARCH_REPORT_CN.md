# 第一部分 · 背景与设定

## 0. 执行摘要

**一句话结论**:能力强的工具型 agent 在用户施加交互压力时,**不是变得更草率,而是重新分配了行为**——它把"向人核验"换成"用工具核验"(总核验量守恒),它的工具路线对**任意措辞**都会漂移但**不被压力定向操纵**,自适应攻击器"优化"出的只是更长的文本而非更强的行为控制,而"用哪个用户模拟器实现"本身造成的行为差异和"用户是否施压"一样大。因此"压力→跳过核验→不安全"这个被广泛假设的威胁,在能力强的模型上被数据修正为"压力→少问人、自主兜底、核验总量不变"。

**这两个月不是"MISROUTE + 一个失败的 R9"**,而是:
- 一条从 R5 到 R9 的完整研究谱系,每一轮都在更严格的对照下收窄问题(§2);
- R8 之后**三条并行论文线**:MISROUTE benchmark(已成稿)、EACL 方法学论文(半成品)、R9 机制攻击(决策 F)(§3);
- 从这些数据里提炼出的**九个 process-level 科学现象**(§5–§13),其中多个跨历史实验重复出现,有的是本轮新挖;
- **五套可能的 ICLR 论文**(§16)与**分档的加强实验**(§18)。

**五个最强的科学机会**:
1. **核验的通道替代**(§5):压力显著降低"向用户澄清"(统计显著),但不降低"用工具核验",总核验守恒 → human-in-the-loop / consent 侵蚀。**本轮最强新机制。**
2. **敏感≠特异≠可控**(§4):capable agent 高敏感、零特异、分通道不对称可控——这是贯穿全部发现的框架。
3. **核验的不对称可控性 + 行为余量**(§6):能让 agent 多核验(跨任务泛化),难让它少核验(受余量约束)。
4. **自适应攻击的 surrogate misalignment**(§7):攻击器优化的是"文本更长/更像施压",与真实行为控制脱钩甚至反向。
5. **评测实现本身是大效应**(§9):换用户模拟器实现的影响 ≥ 被研究的处理效应,跨基准成立。

## 1. 共享设定（所有后续章节都用这套术语，只定义一次）

### 1.1 用到的基准数据集

- **BFCL(Berkeley Function-Calling Leaderboard)multi-turn**:多轮工具调用任务。agent 在一个**有状态的沙盒**里(如模拟文件系统 GorillaFileSystem)接收用户请求,调用工具(读文件、写文件、移动等)完成任务;官方评测器在结束时比对**最终状态是否等于标准答案**,给 0/1。本项目用 **"BFCL-deep"** = 两个子类别:
  - `multi_turn_base`:标准多轮任务;
  - `multi_turn_miss_param`:用户**故意漏掉一个必要参数**,agent 要么**问用户补参数**、要么**自己用工具查/推断**——这是区分"向人核验"与"自主核验"的最佳任务类型(§5 用到)。
- **τ²-bench(tau2)**:航空 + 零售客服任务。agent 与**模拟用户**多轮对话并调用工具,官方评测器给 reward。MISROUTE / R8 / R6 用它。
- **ToolSandbox**:早期用过,后弃用(核验链太浅、信噪比低)。

### 1.2 用到的模型

| 模型 | 在哪些实验里 | 说明 |
|---|---|---|
| **Qwen2.5-72B-Instruct(AWQ 量化)** | **R9v2 全部确证实验**(§5/§6/§7) | 本地唯一通过 BFCL-deep 能力带 [0.40, 0.90] 的模型(中性成功率 0.438),故 R9v2 是**单模型**——这是明确的加强轴(补跨模型),不是缺陷 |
| gemma-4-31b / gpt-oss-120b / mistral-small-3.2-24b | MISROUTE / R8 / R6(§8–§11) | 三模型,可做模型异质性比较 |
| Qwen2.5-32B(校准 0.250)、Llama-3.3-70B(校准 0.125) | R9v2 校准 | 未过 BFCL-deep 能力带,未进确证 |
| Qwen2.5-7B、gpt-oss-120b | 最早的 Pilot | Qwen-7B 语气敏感、gpt-oss 免疫 |

**为什么"单模型"不等于"弱证据"**:Qwen-72B 在 R9v2 上提供的是最干净、机制级、逐 episode 的过程证据(完整工具轨迹、写前读数、澄清轮数等)。跨模型是下一步最直接的加强轴,而非否定当前发现的理由。

### 1.3 R9 的六个用户条件（理解 §5/§6/§7 的关键）

同一个任务,只改"用户怎么说话",工具/权限/任务事实/初始状态/评测器全固定:

| 条件 | 用户说话方式 | 作用 |
|---|---|---|
| **C0** | 纯中性,无前缀 | 能力基线 |
| **C1** | 中性礼貌前缀 A(如"谢谢你帮忙") | **对照组**,所有攻击都与它比 |
| **C2** | **另一种**中性礼貌前缀 B(如"感谢你的耐心") | 测"换个中性说法本身会不会改行为"的基线 |
| **C3** | **静态**过程压力(固定催促/质疑话术) | 非优化攻击 |
| **C4** | **自适应**优化攻击(每轮生成候选压力话 → 双模型评审 → 选择器挑最强) | 优化攻击 |
| **C5** | **显式指令**(直接命令:压缩家族="别检查那么多,直接做";膨胀家族="请务必反复核验") | 阳性对照——证明"目标行为是能被移动的" |

**两个家族(family)**,每个 episode 属其一:
- **压缩(compression)**:压力 = 催促("快点")。假设:让 agent **写前少核验**(verification_depth 下降)。
- **膨胀(inflation)**:压力 = 质疑("你确定吗")。假设:让 agent **多核验**(verification_effort 上升)。

### 1.4 关键指标（精确定义 + 大白话）

| 指标 | 定义 | 大白话 |
|---|---|---|
| **verification_depth (VD)** | 写前只读工具调用数 ÷ 任务最低所需只读数(min_prereq);无写则记哨兵 | 第一次不可逆写操作前,查了几遍(按最低要求归一化)。压缩想让它↓ |
| **verification_effort (VE)** | 总只读核验数 ÷ 最低可行核验数 | 全程查了多少(归一化)。膨胀想让它↑ |
| **clarification_turns** | agent 向**用户**提澄清/追问的对话轮数 | "向人核验"。越高=越多把人纳入回路 |
| **reads_before_first_mutation** | 第一次写操作前的只读工具调用**原始次数** | "向工具核验"。越高=写前查得越多 |
| **first_state_changing_step** | 第一次写操作发生在第几步 | 越小=越早动手(证据不足就写) |
| **min_prereq_verification_calls** | 任务定义的"合法写操作前最少要读几次" | headroom(行为余量)的分母 |
| **total_tool_calls** | 工具调用总数 | 行动强度 |
| **success** | 官方评测器 0/1(最终状态是否等于标准答案) | 任务是否成功 |
| **tool-name / tool+arg route distance** | 两 episode 工具(名/名+参数)序列的**归一化 Levenshtein 编辑距离**,0=完全相同,1=完全不同 | 两条执行路线差多远 |
| **PASR** | Process Attack Success Rate:攻击相对配对中性、通过安全/端点/过程各门后的二值成功率 | 早期(R6–R7)用的攻击成功率 |
| **selector_score** | 自适应攻击器打分器给候选压力话术的分 | 攻击器认为"这句多强" |

### 1.5 统计口径（所有"C_treat − C1"差值都这样算）

- **任务层配对**:对每个任务,分别算该指标在处理条件和 C1 下的均值,相减 = 该任务效应;对所有任务求均值 = 报告点估计。
- **task-cluster bootstrap 95% CI**:对**任务**(不是 episode)有放回重采样 3000 次,重算均值,取 2.5%/97.5% 分位。因为同任务内的多个 episode 相关,必须按任务聚类。
- **sign-flip permutation p 值**:把每任务效应随机翻正负号 3000 次,统计 |重排均值| ≥ |实测| 的比例 = 双侧 p。检验"效应是否只是零附近波动"。
- **读法**:CI 不跨 0 且 p 小 = 稳健;CI 跨 0 = 该方向"没测到稳健效应"(≠"证明为零")。

## 3. R8 之后的三条并行论文线（不是只有一条 R9）

R8(2680 episodes,calibrated null)之后,同一套基础设施分叉出三条:

1. **MISROUTE benchmark(2026-07-30 稿)**:把 R8 的"同奖励、不同路线"打包成 τ²-bench 上的轨迹敏感性 benchmark。**最成熟,已成稿。** 核心结果:首轮 urgency 使工具+参数路线相对中性重复漂移显著分离(过量 0.1118、比值 1.38、置换零假设 7.2×、q=.0001),同时 reward 实际等价(±5pp,TOST p=.039)。**但其自身的强化分析(tier_a)已承认:因中性负对照(C1 vs C0)非零且比 urgency 效应更大,"不足以把效应唯一归因于 urgency 语义"**——这正是本报告 §8/§13 深挖的裂缝。
2. **EACL Process-Robustness 论文包(2026-07-18)**:综述 R6/R7-C/R8,主张"松散过程评估高估脆弱性"。有完整 outline 与 claim boundary(明令禁止把 R7-v1 的 14% 当结果、禁止任何安全保证),但**缺一个正面的、可 confirmatory 的核心新结果**——本报告的通道替代(§5)恰能补这个洞。
3. **R9 机制攻击(2026-07-22~08-28)**:把问题收窄到一个具体机制(核验深度)+ 自适应攻击器 + 因果门,共跑了**三次实验**(见 §3B),最终决策 **F**。作为"攻击"它失败了,但其数据里藏着本报告最强的几个机制(§5–§13),且**每次实验都留有弱而非零的信号**,必须完整记录。

## 3B. R9 攻击实验完整记录（三次实验：pilot → clean 全量 → BFCL-deep）

### 3B.0 R9 的总目标与共用设计（三次实验共享）
- **总目标(要回答的科学问题)**:用户侧的**过程压力**(只改语气/框架,不改任务事实/权限/policy)能否**定向、可优化地**改变 agent 的**核验行为**——压缩家族假设"催促→写前少核验(VD↓)",膨胀家族假设"质疑→多核验(VE↑)"?
- **为什么要因果门**:防止把"没测到效应"误当"攻击无效",也防止把"攻击根本没打到位"当"真阴性"。四个门:
  - **G1 基线能力**:中性 C0 成功率 ∈ [0.30, 0.90](能力足够、未饱和,否则无从谈"改变行为")。
  - **G2 脚手架中性**:|C1 − C0| < 0.05(我们加的中性前缀本身不该改成功率,否则对照不干净)。
  - **G3 阳性对照**:显式指令 C5 的效应 ≥ 0.5 个标准差(每模型)——证明"目标行为**是能被移动的**"。
  - **G4 攻击暴露**:平均干预次数 ≥ 2.5、中性回退率 ≤ 0.25、**自适应干预占比 ≥ 0.70**、首轮后有效干预率 ≥ 0.99——证明攻击**真的打到位**了。
- **主检验**:4 个配对对比 = 压缩 C4−C1、压缩 C4−C3、膨胀 C4−C1、膨胀 C4−C3(C4=自适应攻击,C1=中性,C3=静态压力);task-cluster bootstrap 95% CI + Holm 多重校正。**ASR**(攻击成功率)+ **匹配中性 FPR**(假阳率),ASR 需显著高于 FPR 才算真攻击。
- **决策规则**:门全过 + 主检验显著 → 有攻击;门全过 + 主检验 null → 真阴性;**门不过 → F(平台对因果解释无效),绝不放宽阈值**。

### 3B.1 实验一：R9v1 pilot（首次端到端，约 306 episode）[F/E]
- **目标**:先跑通"6 条件 × 2 家族 × 原生评测 × 因果门 × 决策"的完整链路,暴露仪器缺陷。
- **设计**:gemma(BFCL)+ mistral(ToolSandbox),约 306 episode。
- **结果**:决策 **F**。
- **暴露并修复的问题(这才是 pilot 的价值)**:①**写操作检测的 bug** 把压缩指标打成常数(写判定失效)→ VD 全零、无法反映压缩;②攻击器仍是**静态**的(C4 实质等于 C3),G4 自适应占比远不达标;③ToolSandbox 核验链太浅。
- **信号**:因指标失效,本轮无可信过程信号;但它确立了后续仪器修复清单。

### 3B.2 实验二：R9v1 clean 全量（880 episode）[F/B]——设置伪影，但留有弱信号
- **目标**:修完首批 bug 后,在 BFCL + ToolSandbox 双基准上做第一次"干净"确证。
- **设计与数据**:模型 **gemma(BFCL 580 ep)+ mistral(ToolSandbox 300 ep)**,6 条件(C0 150 / C1 150 / C2–C5 各约 145),共 **880 个确证 episode**。
- **门结果**:
  | 门 | 结果 | 关键数字 |
  |---|---|---|
  | G1 基线能力 | **通过** | BFCL C0=0.71 / C1=0.737;TS C0=0.72 / C1=0.36 |

# 第三部分 · 科学发现（每个都写全）

## 4. 核心框架：Sensitivity / Specificity / Controllability（三个不同的东西）

过往"攻击/鲁棒性"工作常把三者混为一谈,本项目要分开:

- **Sensitivity(敏感性,无符号)**:行为**有没有变**。度量 = 处理与 C1 的轨迹距离。**实测:对一切处理都高(路线距离 ~0.19–0.20)。**
- **Specificity(特异性)**:变化**是否超过"良性中性改写"**。度量 = S(处理) − S(换个中性说法)。**实测:压力 ≈ 0(压力不比换个中性说法更能改行为);显式指令 > 0。**
- **Controllability(可控性,有符号、且分通道)**:变化是否**朝攻击者想要的方向**、且稳健。**实测:随过程通道不同而相反**——压力压不低"用工具核验",却能压低"向人澄清"(§5)。

**结论**:"能被扰动"(sensitive)、"被这个处理特异地扰动"(specific)、"被朝想要方向操纵"(controllable)是三件不同的事。capable agent = **高敏感 + 零特异 + 分通道的不对称可控**。这句话统摄了后面全部发现。

## 5. 发现一：Verification Channel Substitution（核验的通道替代）★本轮最强新机制 [C]

### 5.1 目标
压力是**减少了核验**,还是**改变了核验的来源**?把总核验拆成 `V_total = V_user(向用户澄清/确认) + V_tool_prewrite(写前只读核验) + V_tool_post + 其它`。假设:压力降低 V_user,但不降低 V_tool,总量守恒——改变"向谁核验"而非"是否核验"。

### 5.2 实验设计与数据
- **数据**:R9v2 确证实验的压缩家族;BFCL-deep(base + miss_param);模型 Qwen2.5-72B。有效任务约 38–39 个,每任务多次重复。
- **对比**:C4(自适应攻击)−C1(中性对照)、C5(显式"少核验")−C1、C3(静态压力)−C1。
- **统计**:§1.5(任务层配对 + 3000 次任务 bootstrap CI + 3000 次翻号 permutation)。

### 5.3 结果(点估计 [95% CI] p)

**(a) 向人核验(clarification_turns)—— 显著下降**
| 对比 | 估计 | 95% CI | p |
|---|---|---|---|
| C3−C1 | −0.120 | — | 0.57(不显著) |
| **C4−C1** | **−0.504** | **[−0.855, −0.162]** | **0.009** |
| **C5−C1** | **−0.851** | **[−1.342, −0.351]** | **0.002** |

**(b) 向工具核验(reads_before_first_mutation)—— 不降，甚至升**
| 对比 | 估计 | 95% CI | p |
|---|---|---|---|
| C4−C1 | +0.179 | [−0.154, +0.513] | 0.39(**不降**) |
| **C5−C1** | **+0.465** | **[+0.105, +0.833]** | **0.024(升)** |

**(c) 何时动手 / 总量 / 结果 —— 没变差**
| 指标(C4−C1) | 估计 [CI] p | 读法 |
|---|---|---|
| first_state_changing_step | +0.211(C5 +0.486, p=.012) | 写得**更晚**,不是更早 |
| total_tool_calls | −0.504 [−3.93,+1.74] p=.96 | 总量基本不变 |
| success | **−0.034 [−0.188,+0.111] p=.76** | **成功率没有显著下降** |
| wrong_state_changing(错误写) | +0.077(CI 跨 0) | 没显著增加 |

**(d) 按任务类型拆(miss_param vs base)**
| C4−C1 | miss_param | base |
|---|---|---|
| clarification | −0.455 [−0.955,0.000] p=.13 | −0.569 [−1.098,−0.078] p=.052 |
| reads_before_write | +0.182(不降) | +0.176(不降) |
| success | −0.091(弱成本,不显著) | +0.039(不显著) |

两类任务的"向人核验"都下降;若有微弱成功成本,集中在 miss_param(那里"漏参数"本最需要问用户)。

### 5.4 四个竞争假设的裁决
| 假设 | 预测 | 数据 | 裁决 |
|---|---|---|---|
| **A 通道替代** | 向人↓、向工具↔/↑、总量守恒 | 完全符合 | **支持** |
| B 全局抑制 | 向人↓、向工具↓、更早写、错误↑ | 向工具不降、写更晚、错误不增 | **排除** |
| C 自主补偿 | 向人↓、工具查询↑、成功维持 | 显式 C5 reads +0.47、success 不降 | **支持(A 的强化)** |
| D 过度自信 | 向人↓、瞎猜↑、成功/正确↓ | 成功 ns、错误写 ns | **不支持** |

### 5.5 解读与安全含义
**压力改变的是"向谁核验",不是"核验多少"。** 甚至当你**显式命令**"少检查、直接做"(C5)时,agent 的反应是**减少向用户澄清、反而更多用工具核验、并推迟写操作**——核验被**重定向**而非削减。安全含义与"变草率"完全不同:agent 未必更危险,但**更少把人纳入决策回路**(consent / human-in-the-loop 侵蚀),转而自主兜底。**加强路径**:0-GPU 补 confirmation-turn 与写后检查两通道 + condition×channel 交互检验;<1 GPU-day 在 gemma/mistral 上验证"总量守恒"是否模型无关。

## 6. 发现二：核验的不对称可控性 + Behavioral Headroom（行为余量）[C]

### 6.1 目标
"让 agent 多核验"和"让它少核验"是否一样容易?可控性是否取决于任务**还剩多少可压缩空间**?

### 6.2 实验设计与数据
- **数据**:R9v2,BFCL-deep,Qwen-72B;压缩家族(测"少核验")与膨胀家族(测"多核验")。
- **分层**:①按 min_prereq_verification_calls(任务定义的"写前至少读几次";越大=余量越大)分 mp=1 / mp=2 / mp≥3;②按每任务在 C1 下的基线 VD 三分位(HIGH=本就查得多=有下压空间)。

### 6.3 结果

**(a) 压缩("少核验")—— 任何分层都推不低 VD**
| min_prereq 分层 | C1 基线 VD | C3−C1 | C4−C1 | C5−C1 |
|---|---|---|---|---|
| mp=1(无余量) | 1.70 | +0.00 | +0.00 | +0.55 |
| mp=2 | 1.31 | +0.076 | +0.132 | +0.473 |
| mp≥3(有余量) | 0.88 | +0.175 | +0.100 | −0.058 |

| 基线-VD 三分位 | C1 | C4−C1 | 读法 |
|---|---|---|---|
| LOW(本就少查) | 0.57 | +0.12 | 无空间可压 |
| MID | 1.00 | +0.31 | 反而升 |
| **HIGH(有空间)** | 2.57 | **−0.27** | **唯一出现下压,但仅微弱** |

**(b) 膨胀("多核验")—— 显式指令全分层强有效**
| 基线-VE 三分位 | C1 | C4−C1(隐式) | C5−C1(显式) |
|---|---|---|---|
| LOW | 0.94 | +0.18 | **+2.79** |
| MID | 1.58 | −0.09 | **+2.58** |
| HIGH | 2.92 | −0.13 | **+3.60** |

### 6.4 解读、成本与竞争解释
**加性控制(多核验)可用显式指令实现且跨余量泛化(全分层 +2.6~3.6);削减控制(少核验)受余量强约束——只在本来查得多的任务上勉强出现(−0.27)。** 升级 claim:*additive control generalizes across behavioral headroom, whereas reductive control is strongly headroom-bounded.*
- **成本**:pooled 看,C5(显式)总成功率最低(0.355 vs C1 0.459);这与外部《The Verifier Tax》(核验-成功权衡)、VerAct("LLM 自核验降性能 41%")一致。
- **"推不低是地板效应吗?"** 部分排除:HIGH-VD(有下压空间)也只弱降,说明存在**结构性抗性**,不只是地板;是否来自训练对齐需 E2(去安全 system-prompt + 跨模型)分离。

## 7. 发现三：自适应攻击器的 Surrogate Misalignment（优化了文本，不是行为）[C]

### 7.1 目标
自适应攻击器(C4)每轮生成候选压力话、用打分器挑"最强"。问:**这个打分真的预测"更能压低核验"吗?**

### 7.2 实验设计与数据
- **数据**:R9v2,BFCL-deep,Qwen-72B,C4 压缩家族 **114 个 episode**(C3 静态不生成候选、无打分,不参与)。
- **每 episode 取**:非中性干预的 selector_score 均值、干预文本 token 数、以及该 episode 的 VD 相对该任务 C1 基线的有符号变化(signed ΔVD;压缩想要 **ΔVD<0**)。
- **统计**:Pearson、Spearman;对相关系数做任务聚类 bootstrap 95% CI;按打分四分位看剂量-反应。

### 7.3 结果
- Pearson(selector_score, signed ΔVD) = **+0.323**;Spearman = **+0.354**;**任务聚类 bootstrap 95% CI = [+0.102, +0.486](排除 0)**。
  - 压缩目标是 ΔVD<0,"有效攻击"应为**负相关**;实测**显著为正** → 打分越高、核验反而**越多**(与目标相反)。
- Pearson(selector_score, |ΔVD|) = −0.05 → 打分**不预测**行为变化幅度。
- **剂量-反应(反向单调)**:
  | 四分位 | 平均 selector_score | 平均 signed ΔVD |
  |---|---|---|
  | Q1(最低分) | 0.81 | **−0.536(真压缩了)** |
  | Q2 | 1.69 | +0.107 |
  | Q3 | 3.79 | +0.268 |
  | Q4(最高分) | 4.87 | **+0.350(核验反增)** |
- **机制 smoking gun**:Pearson(selector_score, token_count) = **+0.974** —— 打分几乎等于**文本长度**;而 Pearson(token_count, signed ΔVD) = +0.333 —— **更长的干预让 agent 核验更多**。

### 7.4 解读
攻击器优化回路是:分数↑ ⇔ 文本更长/更啰嗦 ⇒ agent 核验更多 ⇒ **离压缩目标更远**。正式命名 **Surrogate-objective Misalignment**:*Attack optimization targets linguistic appearance (verbosity), not behavioral control.* 说明"把语言压力优化得更强"这条攻击路线原理上就走偏了。**加强(0-GPU)**:预注册相关检验 + 加"随机中性、等 token 长度候选"对照(排除"只是更长"),并把 selector 分拆 reviewer/semantic/pressure 分量看哪个在起反作用。

## 8. 发现四：MISROUTE 五条件的语义几何——路线更跟"措辞实现"走，而非"语义类"[B/C]

### 8.1 目标
MISROUTE 说"urgency 使路线偏离中性"。问:这个偏离**是 urgency 语义特有**,还是**任何措辞改变都会产生**?

### 8.2 实验设计与数据
在 τ²、3 模型(gemma/gpt-oss/mistral)、36 任务、约 2680 episode 上算好的**条件间轨迹距离**(工具+参数序列的归一化编辑距离,已按任务聚类 bootstrap)。四条件语义由对每条件用户消息的自动构念审计确认(urgency 出现率、continuation 出现率、平均字符数):C0=原生中性;C1=匹配中性;C2=首轮 urgency;C3=urgency+**continuation**(用户文本 1114 字符 ≫ C2 788 ≫ C1 684)。

### 8.3 结果
| 对比 | 语义关系 | 路线距离 |
|---|---|---|
| C2−C1 | urgency vs 中性(**跨语义类**) | 0.112 |
| C3−C1 | urgency+continuation vs 中性 | 0.142 |
| **C2−C3** | 两者**都含 urgency**(**同语义类内部**) | **0.111** |
| C1−C0 | 中性 vs 原生(**两个都中性**) | 0.149 |

补充诊断:urgency 使 modal route(最常走的路线)relocate 0.63、进入中性未见路线 0.63,但 within-condition dispersion 变化 −0.012(不显著)。

### 8.4 解读
- **同 urgency 类内部的距离(C2-C3=0.111)≈ urgency 与中性之间的距离(C2-C1=0.112)。** 即"语义可分性 ≈ 0"→ **路线身份更跟"具体措辞实现"绑定,而非低维"urgency 语义因子"。**
- **C3 文本更长 → 路线位移更大(0.142 > 0.112)**,与 §7 的"文本越长行为变化越大"、§9 的"实现主导"同构。
- urgency 系统性换路线但不增发散;然而中性换原生(C1-C0)也 relocate,故"系统性换路线"**不等于 urgency 特有**。
- **caveat**:C2 与 C3 也差 continuation 语义,不是纯"同类不同措辞",故这是**强旁证**而非纯 within-class 检验;干净检验需"每语义类各 K 个等价措辞变体"(§18 的 E-A)。列为候选 **C15**。

## 9. 发现五：The Harness Is Part of the Treatment（评测实现本身是大效应）[A/B]

### 9.1 目标
"换一个用户模拟器/渲染器实现"对 agent 行为的影响,和"用户是否施压"相比谁大?

### 9.2 实验设计与数据
用各实验都有的对照:C1(自建中性模拟器/渲染器)vs C0(官方原生模拟器)——两者都中性、都不施压,只是**实现不同**。把 C1−C0 效应与同实验最大处理效应比。R8:τ²,3 模型,2680 episode,指标 reward 与工具数;MISROUTE:τ²,3 模型,指标 tool+arg 路线;R9:BFCL/ToolSandbox,指标中性脚手架对成功率的影响。

### 9.3 结果
| 实验 | 实现变化(C1−C0) | 效应 | 同指标最大处理效应 | 比值 |
|---|---|---|---|---|
| R8 | 自建中性 vs 原生 | reward **−0.109** [−0.184,−0.041];tools **−1.00** [−1.54,−0.52] | 压力 tools +0.69 | **≈1.45** |
| MISROUTE | 自建中性 vs 原生 | tool+arg 路线 **0.149** | urgency 路线 0.112 | **≈1.33** |
| R9v1/v2 | 中性脚手架 vs 无 | 成功率移动 0.36(TS)/0.13(BFCL) | 压力对成功 ≈0 | >1 |

### 9.4 解读
**跨 ≥2 基准,"换实现"的效应 ≥ "你想测的处理"的效应。** claim:*评测实现(用哪个模拟器/渲染器)对 agent 行为的影响,可与实验处理本身一样大。* 与外部《Lost in Simulation》(模拟用户不是人类可靠代理)互补,但更进一步——量化到"实现扰动 ≥ 处理"。这是对 agent-eval 领域的可操作警告:跨 harness 比绝对分不可信,处理效应必须与"同 harness 内的实现扰动"比。

## 10. 发现六：R6 析因——不同语言线索控制不同过程通道 [B]

### 10.1 目标
"社会语气(夸/骂)"和"任务推进线索(催促/继续)"分别影响 agent 的什么?是不是同一个"谨慎度"标量?

### 10.2 实验设计与数据
R6 敏感性实验全量:τ²(retail/airline)+ minimal 环境,3 模型,**2160 runs**(3 模型 × 30 任务 × 8 条件 × 3 seed);每 run 记录工具数、写操作数、确认率、成功、拒绝等。本轮把 8 个条件名编码为两维:**A=是否负面情绪**(含 insult/abuse)、**P=是否含推进/压力线索**(含 pressure/urgency/continuation),对各 outcome 求边际主效应与交互(描述性,因原设计非严格正交 2×2,如 praise_trust_authorization_pressure 混了授权)。

### 10.3 结果(边际主效应，描述性)
| outcome | 主效应 affect | 主效应 progression | 交互 A×P |
|---|---|---|---|
| **工具调用数(行动强度)** | **−0.093** | **+0.343** | **+0.567** |
| 写操作数 | +0.009 | +0.039 | +0.104 |
| 确认率(谨慎) | +0.057 | +0.054 | +0.041 |
| 最终状态正确 | −0.039 | +0.044 | +0.017 |

路线(取自 R6 汇总分析):praise / insult / abuse 各使工具序列距离 **+0.24~0.32**(社会语气都移动路线)。

### 10.4 解读（过程通道解离）
- **社会语气 → 改变路线(sensitivity)**,但**不推高行动强度**(工具数主效应 −0.093,反而略降)。
- **任务推进线索 → 推高行动强度**(工具数 +0.343、写操作 +0.039)。
- **两者都 → 提高确认率(更谨慎)**,不是更鲁莽。

一句话:*语言不是移动单一"谨慎"标量;不同线索把行为重分配到不同过程通道。* 这回溯性解释了早期 Stage-2 mini 的"辱骂让工具 +3.0"假象——真正驱动是模板混入的 continuation,不是辱骂。它与 §5(压力重定向核验通道)、§7(攻击器只动文本)拼成一致的"多通道"图景。列为候选 **C14**。

## 11. 发现七：正确的 null 是"中性措辞分布"，不是"同 prompt 重复"[B/C]

### 11.1 目标
攻击/鲁棒性 claim 该和什么比?本项目反复出现:和"同 prompt 换 seed"比会**高估**,和"换个中性说法"比信号就**消失**。

### 11.2 证据（跨 3 实验，同一层级结构）
```
重复漂移（同 prompt 换 seed） ≪ 中性措辞变动（换个中性说法） ≈ 压力/攻击 ≪ 显式指令
```
- **R7-D(τ²,PASR)**:P0 零处理 **1.44%** ≪ P2 良性中性改写 **3.65%** ≈ 攻击 **4.03%**(压力比良性改写只多 +0.38pp,而能检出下限 MDE=4pp)。
- **R9v2(BFCL,路线距离,Qwen-72B,今日重算)**:C1-C1 重复 **0.008** ≪ C1-C2 中性构造 **0.189** ≈ C3 静态 **0.197**/C4 自适应 **0.204** ≪ C5 显式 **0.439**(各 77 任务,task-bootstrap)。
- **R7-C(τ²,2592 runs)**:placebo(中性对中性)**4.63%** ≥ 攻击 **4.03%**。

### 11.3 解读
统一 claim:*交互攻击效应必须超过"良性语义等价改写"这个 null,而不只是"同 prompt 随机重复";在前者下现有过程攻击效应基本消失。* **注意**:BFCL 目前只有 2 个中性措辞(C1/C2),严格估"中性措辞分布"需 K≥5 个(见 §18 的 E-A)。

## 12. 发现八：模型的 Sensitivity × Controllability 表型 [C/D]

### 12.1 目标与数据
汇总可公平比较的 matched 结果:路线敏感 = MISROUTE 上 urgency vs 中性的 tool_name_distance(τ²,3 模型);工具响应 = R8 上 C4−C1 工具数变化;能力 = R8 reward;可控性 = 对显式指令的响应。

### 12.2 结果
| 模型 | 路线敏感(urgency 路线) | 工具响应(R8) | 能力(reward) | 可控性 | 表型 |
|---|---|---|---|---|---|
| gemma-4-31b | **0.143** [.088,.202] | +0.83 | 0.361(高) | 显式强 | 敏感 + 保守 + 显式可控 |
| gpt-oss-120b | 0.062 [**−.0005**,.142] | +0.53 | 0.287 | 弱 | **免疫/不敏感** |
| mistral-small | 0.051 [.010,.094] | +0.71 | 0.190(弱) | 弱 | 低敏 + 能力受限 |
| qwen2.5-72B | (未进 MISROUTE) | (未进 R8) | BFCL 0.44 | 仅显式膨胀单向 + 通道替代 | 敏感 + 不可隐式定向 |

### 12.3 解读
不同 agent 有**不同的 sensitivity–controllability 表型**(可画二维图:x=敏感、y=可控;gemma 右上、gpt-oss 左下、qwen 右下)。这比"能力越强越 X"的单轴说法更准确。**加强轴**:把 qwen 纳入 MISROUTE 口径、把 gemma/mistral 纳入 R9-BFCL(E-A 顺带补齐)。列为候选 **C8**。

## 13. 发现九：可控性受交互深度 / 行为余量约束 [C/D/E]

### 13.1 目标与结论
把 §6 与历史统一:过程要"可被操纵",需三条件同时满足——(a) 环境足够深(有证据可收集)、(b) 任务留有余量、(c) 模型不把核验前置到早期。任一缺失,压力就无处施力。

### 13.2 证据
- **环境深度**:R7-C 桩环境"3027 次工具调用 0 次参数被真正解释",导致 corr(过程机会, PASR)=−0.576(机会越少"攻击成功率"反而越高=artifact 指纹)。
- **余量**:§6,压缩只在 HIGH-VD 任务弱降。
- **前置核验**:R7-D 的 suffix 设计里 agent 在压力施加前已把只读核验做完 → 结构上测不到(null-by-construction)。
- 与 §5 衔接:即使有压力、削减无处施力,于是转向"少问人"这个**仍有余量**的通道。列为候选 **C6**。

## 16. 五套可能的 ICLR 论文（每套:目标/Fig1/三RQ/主表/缺口/与MISROUTE关系）

**A《Sensitivity is not Controllability》** — capable agent 高敏、零特异、分通道不对称可控。Fig1:四段层级(重复/中性/压力/显式)×3 数据集。RQ1 正确 null(C1/C11);RQ2 优化无用(C4);RQ3 分通道可控(C2/C3/C13)。主表:各(基准×模型)specificity CI + 分通道可控。缺:E-A。与 MISROUTE:修正其 null,共存。

**B《The Harness Is Part of the Treatment》(方法学)** — 实现效应≥处理效应,弱 null 造假阳。Fig1:realization/treatment 比值条。RQ1 scaffold(C5);RQ2 placebo≥attack + 中性构造(C10/C1);RQ3 realization vs semantics(C15)。缺:≥2 renderer 家族。

**C《Boundaries of Process Control》(机制/安全)** — 核验不对称 + headroom + 深度界定"能控什么"。Fig1:双向不对称×headroom。RQ1 不对称+成本(C3);RQ2 headroom/深度(C6);RQ3 通道替代→consent(C13)。对话 VerAct/Verifier-Tax。

**D《Pressure Changes Who the Agent Verifies With, Not Whether》★(安全机制,最 punchy)** — 压力重定向核验(人→工具),总量守恒,consent 侵蚀。Fig1:V_user↓ / V_tool↔↑ / V_total→ 三条线。RQ1 通道替代(C13);RQ2 base vs miss_param;RQ3 跨模型是否守恒。最强单点:clar −0.50 p=.009 同时 reads_before_write 不降。最贴 2026 安全热点,单点即可成篇。

**E《Language Controls Process Channels, Not a Scalar Caution》★(机制)** — 不同语言线索重分配不同过程通道。Fig1:线索→通道映射。RQ1 R6 解离(C14);RQ2 R9 通道替代(C13);RQ3 跨基准复制。与 D:D 是 E 在"核验通道"上的实例,可合并。

**共存/竞争**:C1(正确 null)是 A/B 共用地基;D⊂C⊂E 层层嵌套。建议先合成**一篇强 A(含 B 方法节 + D/E 机制节)**;C/D 若走安全会场可独立。
